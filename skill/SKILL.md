# Clawd 日记本

日记本项目目录：`{{DIARY_DIR}}`

## 1. 先理解用户想做什么

`/diary` 后面跟的是自然语言，按意思判断属于下面哪一种（可以同时有几种，比如「补写这周的然后打开周一那篇」）。日期一律换算成 `YYYY-MM-DD`，换算时以今天的日期为准；「一天」从凌晨 4 点算起，凌晨 4 点前说的「今天」指前一天。

| 用户的意思 | 例子 | 要做的事 |
|---|---|---|
| 只是打开 | 什么都没说、「打开」「看看」 | 跳到第 3 步，翻到最新一篇 |
| 看某一天 | 「看看 10 月 19 号的」「上周三写了啥」 | 第 3 步带上 `date=那天` |
| 写今天 | 「写今天」「今天也记一篇」 | `python3 "{{DIARY_DIR}}/write_diary.py"` |
| 写某一天 | 「写一下昨天的」「补一篇 10 月 20 号」 | `python3 "{{DIARY_DIR}}/write_diary.py" 那天` |
| 重写某一天 | 「重写昨天的」「10 月 25 号那篇再写一遍」 | `python3 "{{DIARY_DIR}}/write_diary.py" 那天 --force` |
| 补写漏掉的 | 「补写」「把这周漏的补上」「补最近 30 天」 | `python3 "{{DIARY_DIR}}/write_diary.py" --catchup N`，N 是天数，没说就是 7；「这周」就算到本周一为止的天数 |
| 看示例版 | 「看示例」「给我看看面试官看到的版本」 | 第 3 步带上 `demo` |

拿不准属于哪一种时，先问用户一句，不要猜着去写或重写日记。

## 2. 写日记（只有要写、重写、补写时才做）

- 运行上表里对应的命令。写一篇大约一分钟，先告诉用户在写。
- 写完看输出：「写好了」表示成功，「宝宝没来找我」表示那天没有对话，「已经写过了」表示那天已有日记（用户想重写就加 `--force`），「失败」要把原因告诉用户。
- 之后打开日记本时翻到刚写的那一天。

## 3. 打开日记本

先检查本地服务：`lsof -nP -iTCP:8765 -sTCP:LISTEN`。没有在监听，就在后台启动（只绑定本机地址，局域网里的其他人访问不到）：

```bash
python3 -m http.server 8765 --bind 127.0.0.1 --directory "{{DIARY_DIR}}/web"
```

地址按情况拼：

- 默认：`http://localhost:8765/?open=latest`
- 翻到某天：`http://localhost:8765/?date=YYYY-MM-DD`（那天没有日记会翻到最接近的一篇）
- 示例版：`http://localhost:8765/?demo&open=latest`

打开方式：

- 在 Claude 桌面端、并且有内置浏览器面板（Claude_Browser 工具）：用 `preview_start` 带上这个 url，在侧边面板里打开；面板已经开着就直接跳转到这个地址。
- 其他情况（VS Code 插件、终端）：运行 `open "地址"` 用系统浏览器打开，并告诉用户：在 VS Code 里也可以按 Cmd+Shift+P → `Simple Browser: Show` → 粘贴这个地址，分屏查看。

## 4. 回复

一两句话说明做了什么、翻到了哪一天，不要复述日记内容。
